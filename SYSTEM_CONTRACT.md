# THREE-REPOSITORY SYSTEM CONTRACT — RESET 2026-10-07

## One system, three responsibilities

These repositories are not three products. They are three layers of one project.

1. **Founder-OS** = MEMORY / governance — durable Founder decisions, verified facts, constraints, lessons, evidence, and continuity.
2. **kawasan-masjid-core** = CORE / runtime — canonical project model, application/runtime, Supabase/backend, AI workforce, evidence, economics, APIs, and operational execution.
3. **kawasan-masjid-public** = PUBLIC / external interface — human-facing website, vision, discovery, public information, opportunity gateway, and inbound entry.

## North Star

The project is a long-term **Kawasan Masjid 1.000 Ha / Islamic Eco-City** vision.

The digital ecosystem is the first practical foundation and proving ground. It is not the final product and must not replace the physical vision.

Three pillars:
- digital ecosystem: online + offline coordination and information infrastructure
- public/community products: website first, future Android/iOS/community applications
- real-world realization: mosque-centered place, education, food/agriculture, ecology, economy, housing, public space, technology, and phased physical development

## Founder position

Founder = Originator, System Owner, Strategic Director, Reviewer, Final Accepter, Economic Beneficiary.

AI = research, analysis, implementation, testing, monitoring, documentation, and repetitive operational leverage.

Founder-OS is a memory/governance layer. It does not execute CORE economic operations or directly mutate operational Supabase state.

## Operating loop

VISION → RESEARCH → DESIGN → BUILD → TEST → PROVE → LEARN → REPEAT

Economic loop only when a real external need exists:

REAL NEED → QUALIFY → FOUNDER GATE → DELIVER → ACCEPTANCE → PAYMENT → VERIFIED MARGIN

## Evidence rule

**NO PROOF, NO CLAIM.**

Never claim users, customers, partners, funding, revenue, physical construction, or successful outcomes without evidence.

## Product discipline

No feature is added because it is fashionable, impressive, or technically interesting.

Every feature must answer:
1. Which part of the North Star does it serve?
2. Who uses it?
3. What real problem does it solve?
4. What evidence will show that it works?
5. Which repository owns it?

If those answers are unclear, the feature is deferred.

## Synchronization rule

When architecture, product direction, or truth changes:
- CORE is updated first when runtime truth changes.
- Founder-OS records the durable decision and current state.
- PUBLIC is updated only for information that should be visible externally.

No repository may invent a different project identity.
